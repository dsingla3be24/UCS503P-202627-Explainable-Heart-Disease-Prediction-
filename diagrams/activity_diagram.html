📋 Diagram 1: System-Level Overview

  • The system starts with a decision node selecting between two execution modes: Web Application (python app.py) or CLI Training Pipeline (python main.py)
  • The web app mode initializes a Flask server on port 5001 and loads the ClinicalModelWrapper which trains or loads the CNN-LSTM-Attention model
  • The CLI mode parses arguments via argparse with a further decision for --patient_idx (single patient) vs full pipeline

📋 Diagram 2: Web Prediction Flow

  • Swimlanes: 4 partitions — User/Frontend, Flask/ML, XAI Module, MySQL Database
  • Patient Deduplication: get_or_create_patient() checks if hospital_patient_id exists; creates new record if not
  • Existing Patients: Auto-increments age based on time since last visit using get_patient_last_demographics()
  • Ground Truth Matching: Computes normalized distance to Cleveland CSV dataset; if distance < 0.05, sets true_label from dataset
  • Fork/Join: Three XAI methods (Grad-CAM, Attention, SHAP) execute in parallel, then join before aggregation
  • Second Fork: PDF report generation and API response assembly happen in parallel, then join for DB persistence
  • Database Writes: Two INSERTs — clinical_records (14 params) and ai_diagnoses (probability, class, top 3 drivers, PDF path)

📋 Diagram 3: Single Patient Explanation

  • Triggered via python main.py --patient_idx N where N is a test set index
  • Decision: Checks for pre-trained weights file; if found, loads them; otherwise trains the model first
  • Fork/Join: Grad-CAM, Attention, and SHAP computed in parallel
  • Outputs: XAI comparison chart (PNG), GAF heatmap (PNG), clinical report (TXT), PDF report — all saved to results/patient_N/

📋 Diagram 4: Full Training Pipeline

  • 11 sequential phases covering EDA → Preprocessing → GAF Demo → Tuning → Training → Ablation → CV → XAI Profiling → Global Heatmaps
  • Fork (3-way): CNN, CNN-LSTM, CNN-LSTM-Attention models trained in parallel
  • Two optional decision nodes: --tune enables Keras Tuner RandomSearch; --cv enables 5-fold cross-validation
  • Loop region: XAI profiling iterates over selected True Positive and True Negative test patients
  • Ablation Study: Compares all 3 models across Accuracy, Precision, Recall, F1-Score, ROC-AUC; saves CSV + barplot

📋 Diagram 5: Data Preprocessing

  • Implements preprocess_pipeline() from src/preprocessing.py
  • ClinicalRangeScaler: Uses fixed physiological boundaries instead of dataset-dependent statistics for out-of-sample consistency
  • One-Hot Encoding: Expands 8 categorical features into ~22 binary columns
  • Feature Mapping: Stores original-to-processed column index map, critical for XAI aggregation back to 13 clinical features
  • SMOTE Decision: Conditionally applies Synthetic Minority Oversampling; falls back to class weights if imblearn is unavailable
  • GAF Transform: Converts 1D feature vectors to 2D Gramian Angular Summation Field images for CNN Conv2D input

📋 UML Notation Guide

  • Initial Node (●): Filled black circle — entry point of the activity
  • Activity Final Node (◉): Filled circle inside a circle — termination point
  • Action State: Rounded rectangle — represents a single activity/operation
  • Decision Node (◇): Diamond — branching point with guard conditions
  • Fork Bar (▬ white): Thick white bar — splits flow into concurrent threads
  • Join Bar (▬ white): Thick white bar — synchronizes concurrent threads
  • Merge Bar (▬ gray): Gray bar — merges alternate paths back together
  • Guard Conditions [text]: Boolean expressions on transitions (e.g., [Yes], [No])
  • Swimlanes: Vertical partitions assigning actions to responsible actors/components
  • Loop Region: Dashed boundary — iterative repetition of enclosed activities
